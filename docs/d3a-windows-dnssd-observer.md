# D3A Windows native DNS-SD observer adapter

`tools/windows_dnssd_observer.py` is a Windows-only, evidence-only adapter for a future separately authorized D3. It uses Python standard-library `ctypes` with the Windows 10+ `dnsapi.dll` DNS-SD APIs: `DnsServiceBrowse`, `DnsServiceBrowseCancel`, `DnsServiceResolve`, and `DnsServiceResolveCancel`. The binding and lifecycle are based on Microsoft’s official [browse API](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsservicebrowse), [browse cancellation](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsservicebrowsecancel), [resolve API](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsserviceresolve), and [service-instance structure](https://learn.microsoft.com/en-us/windows/win32/api/windns/ns-windns-dns_service_instance).

The adapter accepts only `_ewelink._tcp.local.`. It starts one asynchronous browse, retains the callback and `DNS_SERVICE_CANCEL` object through cancellation, waits for the documented final browse cancellation callback, then resolves at most eight discovered service names within the original bounded time budget. Each resolve has an explicit cancel path. It has no retry loop, monitor, raw DNS/mDNS packet parser, socket code, or detached worker. The D2A wrapper remains responsible for direct-child timeout/termination; as with D2A, wrapped tools must not daemonize or spawn detached workers.

Native output is intentionally raw D1 input material and must be captured only in D2A’s Git-local private runtime namespace. It is a bounded JSON object containing up to eight `captures`; every capture has the existing D1 fields `service.name`, `service.type`, `service.port`, and `service.txt`. It deliberately omits hostnames, IP addresses, interface indexes, and priority/weight. TXT values, service names, and possible device identifiers remain raw temporary evidence and must not enter Git, documentation, logs, model context, or final reports. A future D3 may transform each capture through `tools/ewelink_capture_analyzer.py`; only that sanitizer’s output can be reviewed or retained.

D3A validation is local and synthetic only. It checks native symbol availability and ctypes structure declaration, synthetic browse/resolve result shaping, bounds, cancellation-budget behavior, D1-compatible conversion, and raw-field output boundaries. It does not call `DnsServiceBrowse` or `DnsServiceResolve`, and it establishes no Network, Hardware, or Matter evidence. D3 remains separately authorized.
