# D3A Windows native DNS-SD observer adapter

`tools/windows_dnssd_observer.py` is a Windows-only, evidence-only adapter for a future separately authorized D3. It uses Python standard-library `ctypes` with the Windows 10+ `dnsapi.dll` DNS-SD APIs: `DnsServiceBrowse`, `DnsServiceBrowseCancel`, `DnsServiceResolve`, and `DnsServiceResolveCancel`. The binding and lifecycle are based on Microsoft’s official [browse API](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsservicebrowse), [browse cancellation](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsservicebrowsecancel), [resolve API](https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsserviceresolve), and [service-instance structure](https://learn.microsoft.com/en-us/windows/win32/api/windns/ns-windns-dns_service_instance).

The adapter accepts only `_ewelink._tcp.local.`. One overall deadline is split into a bounded browse sub-budget, browse cancellation grace, and a positive bounded resolve slice plus resolve cancellation grace. It retains the callback and `DNS_SERVICE_CANCEL` object through cancellation, and waits for the documented final browse cancellation callback. To preserve the single deadline, it resolves only the first discovered service; additional discovery names set `truncated: true` rather than being treated as complete TXT evidence. Each resolve has an explicit cancel path. It has no retry loop, monitor, raw DNS/mDNS packet parser, socket code, or detached worker. The D2A wrapper remains responsible for direct-child timeout/termination; as with D2A, wrapped tools must not daemonize or spawn detached workers.

Resolve ownership is intentionally process-lifetime. Every pending/accepted `DnsServiceResolve` has a `ResolveOperation` retained in a module-level registry. That object strongly owns the callback, request, cancel handle, event and first accepted result until the observer child exits. A first accepted result is immutable; later success, duplicate, malformed, failure or cancellation callbacks are safely ignored/rejected rather than releasing state or replacing it. On a resolve timeout the adapter attempts `DnsServiceResolveCancel`, but does not interpret its return value as callback quiescence and retains the operation. D2A direct-child termination is the final ownership boundary.

Native output is intentionally raw D1 input material and must be captured only in D2A’s Git-local private runtime namespace. It is a bounded JSON object containing at most one first-service `capture`; its D1 fields are `service.name`, `service.type`, `service.port`, and `service.txt`. Additional discovered services are signalled by `truncated: true`, not silently omitted as complete evidence. It deliberately omits hostnames, IP addresses, interface indexes, and priority/weight. TXT values, service names, and possible device identifiers remain raw temporary evidence and must not enter Git, documentation, logs, model context, or final reports. A future D3 may transform the capture through `tools/ewelink_capture_analyzer.py`; only that sanitizer’s output can be reviewed or retained.

D3A validation is local and synthetic only. It checks native symbol availability and ctypes structure declaration, browse/resolve deadline regression cases, process-lifetime late/multiple callback safety, timeout/cancel late callbacks, TXT property fail-closed behavior, D1-compatible conversion, and raw-field output boundaries. It does not call `DnsServiceBrowse` or `DnsServiceResolve`, and it establishes no Network, Hardware, or Matter evidence. D3 remains separately authorized.
